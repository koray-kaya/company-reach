# M8 — Publish Implementation Plan

Issue #8. Branch `feat/8-publish`, cut from `main` (M7 merged as e21868c via
#28). Also carries #25 and #27, moved to this milestone.

The repository has been public since day one, so M8 is not about making it
public. It is about making it **usable and honest by someone who is not its
author**: a fresh clone that installs, checks itself and runs; a page that
says exactly what personal data the tool handles and where it goes; an
evaluation a stranger can run without the author's hand-labelled data; and
the last two follow-ups the earlier milestones filed.

## Open points

Four, answered one at a time before code; all four settled with Koray on
2026-09-24 as recommended.

**1. What does the public golden subset contain?**

**Decided (2026-09-24, with Koray): the evaluations that need no live web**,
as recommended.

The real golden set is real companies and real people, and stays in `data/`.
*Recommendation:* a fictional subset for the evaluations that need no live
web — scoring (fictional register entries with hand labels), extraction
(fictional saved pages with the people and addresses they carry), drafts
(fictional profiles and contacts), and the poisoned page already committed.
Site choice needs real search results and real sites, so its evaluation
stays local. The evals use `data/golden/` when it exists and the committed
subset otherwise, and say which one they ran on.

**2. Do the prompts move into the package?**

**Decided (2026-09-24, with Koray): yes**, as recommended.

*Recommendation:* yes, to `src/company_reach/prompts/`, loaded through
`importlib.resources` like `schema.sql`. They stay plain Markdown files in
the repository, still easy to read and edit; only the folder moves, and
`AGENTS.md` says where.

**3. What does the retention purge remove, and after how long? (#27)**

**Decided (2026-09-24, with Koray): 365 days, the ledger stays**, as
recommended.

*Recommendation:* `company-reach purge --older-than 365` (days) removes, for
every company decided or drawn before the cut-off, its pages and page cache,
profile, contacts, drafts and site evidence, and replaces the reason with
"purged" — the same things `forget` removes. It keeps the ledger and the
suppression list, because "contacted once, ever" rests on them; for a `sent`
row it keeps the address too, since that is the record of what was sent and
the key to honouring a later deletion request. Nothing runs on a schedule by
itself; the README says to run it, and `doctor` reports how much is older
than the cut-off.

**4. Same company name under another TLD (#25)?**

**Decided (2026-09-24, with Koray): the narrow acceptance**, as recommended.

A site on `muster.ch` whose only address is `info@muster.com` is held today.
*Recommendation:* treat the other TLD as on-site only when the address was
read from the page by regex and its label equals the site's label exactly
(`muster.ch` / `muster.com`, not `muster-shop.com`), and mark it `generic`
with a hint on the card. An attacker can register `muster.com`, but a planted
address still has to appear on the company's own verified site to be read
there; the model's persons keep the strict rule.

## Tasks

1. **Prompts into the package** (open point 2). *Test:* the prompt loader
   finds every prompt from an installed wheel, not only from a checkout.
2. **Public golden subset** (open point 1): fictional fixtures and the evals'
   fallback. *Test:* `RUN_LLM_EVALS=1` on a clone without `data/` runs the
   subset and reports it.
3. **Retention purge** (open point 3, #27). *Test:* rows and cache older than
   the cut-off go, the ledger and suppression stay, a `sent` address stays.
4. **#25** (open point 4). *Test:* `muster.ch` with `info@muster.com` read
   from the page is offered as on-site; `muster-shop.com` is not; a model
   person on another TLD stays third party.
5. **CI history check**: a step that fails if `data/` ever appears in git
   history.
6. **`PRIVACY.md`**: what the tool stores and where, what leaves the machine
   (the model endpoint receives page text and names; search queries go to
   SearXNG's engines; nothing is sent to anyone else), tracing off, `forget`,
   `purge`, the ethics gate.
7. **README**: what it does now, setup from a fresh clone with Docker, the
   command sequence from `pool` to `review`, the gate, a pointer to
   `PRIVACY.md`. `.env.example` gains `SENDING_APPROVED=false`.
8. **The private path in `IMPLEMENTATION.md`**, removed from the text.

## Acceptance

- Fresh clone → `uv sync` → `company-reach doctor` → `RUN_LLM_EVALS=1 uv run
  pytest tests/test_prompts.py` runs on the committed subset.
- `git log --all --name-only | grep '^data/'` is empty, and CI checks it.
- `PRIVACY.md` names every place personal data is kept and every party it
  goes to.
- `uv run pytest -q`, `ruff check`, `ruff format --check`, CI green.
